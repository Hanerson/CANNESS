# CAN-212 插件的 SSH 传输不校验主机密钥

| 字段 | 值 |
|---|---|
| 类型 | 安全 |
| 优先级 | **P2** |
| 组件 | `plugin/src/ssh2-transport.ts` |
| 首次发现 | 2026-11-27 只读评估 |
| 状态 | **fixed** |
| 标签 | `ssh`, `host-key` |
| 复核 | 2026-11-27。删除「隧道每次重连都换钥」 |

## 现象

直连 NPU 的连接配置只有 host、port、username、私钥或密码。没有 `hostVerifier`，也没有 known_hosts 路径。`ssh2` 在未提供校验回调时接受对方主机密钥。

2026-11-27 远端复核用 OpenSSH 进入容器，使用的是已受信任的容器主机密钥。这是复核时的 OpenSSH 配置，不是插件传输里的校验。没有证据表明转发隧道每次重连都会更换主机密钥。

## 证据

- `plugin/src/ssh2-transport.ts` 第 309–317 行：`connectConfig` 返回的对象只有 `host`、`port`、`username`，以及可选的 `privateKey`、`password`。
- 已安装的 `plugin/node_modules/ssh2/lib/protocol/kex.js` 在没有 `hostVerifier` 时走默认接受。传输单测注入的是假 client，到不了这段。
- 评测会把算子源码、构建脚本和可能的提交包上传到该主机，并在其上执行。
- 复核进入容器时，OpenSSH 使用受信任的容器主机密钥。插件源码没有相应的 known_hosts 或指纹钉死。

复核订正：初稿推断 CANNLab 隧道每次转发都会换钥。复核没有这项证据，该推断删除。

## 影响

插件发起的连接不核对主机密钥。同一地址上的另一台主机会被接受，测试包和 SSH 密码会送到那台主机。密码经 dsh 凭据存储读取，不会写进 profile。

## 期望

插件的直连在首次连接时展示指纹并写入该 profile 的 known_hosts，之后不一致就失败，且不上传包。复核使用的 OpenSSH 信任配置保持在部署侧，不代替插件传输里的校验。

## 复现

1. 读 `connectConfig`。
2. 对一台改过主机密钥的测试机做 `preflight_evaluation({ remote: true })`。
3. 观察连接成功。不要在生产机上做替换实验。

## 建议修复

- `SftpOptions` 增加可选的钉死指纹或 known_hosts 文件。
- 缺省策略对插件直连是「已记录则必须一致，未记录则失败并返回指纹」，由设置卡确认后写入。
- 单测用假的 host key 回调断言：缺校验器时不调用 `ready`。

## 验收标准

- 插件直连两次主机密钥不同，第二次失败，错误里有指纹，没有上传包。
- 验收不依赖「隧道每次重连都换钥」。有隧道密钥行为的证据之后再单独立项。

## 关联

CAN-201。容器 SSH 与宿主机 SSH 是不同的密钥域，指纹按端点分开记录。

## 处置和验证

直连及手工转发默认需要可信 SSH 主机指纹，错钥拒绝。保留显式兼容开关和原 CANNLab 托管转发路径。
