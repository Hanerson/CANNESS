# 2026-11-19 SwiGLU P0 修复记录（CAN-101 ~ CAN-104）

本轮按 `issues/CAN-101` ~ `CAN-104` 修复 P0 解阻问题。核对基线为 `main@b448190`（2026-11-18）。

## CAN-101 模板 CRLF 导致 Linux 构建失败

**改动**（`plugin/src/package-files.ts`、`plugin/src/submission.ts`）：

- 新增 `normalizeEol()`，`readTemplateBody()` 在读取任何构建契约模板后统一归一为 LF；CANNBench 模板渲染改用同一函数。
- `renderBuildContract()` 在返回前断言所有 `.sh` 不含 `\r`，否则拒绝写包。
- 新增回归测试：故意写入 CRLF 的 `build.sh` fixture 经 `readTemplateBody()` 后为纯 LF；生成包及 `.contract-selfcheck` 的脚本均不含 CR。

**验证**：本地单测覆盖；Windows 工作树生成包后断言为 LF。真机 Linux 编译待复验。

## CAN-102 契约自检在 CANN 9.0.0 不可编译且是硬门禁

**改动**（`plugin/templates/build-contract/canness_tiling.h`、`plugin/templates/local-validation/kernel_operator.h`、`plugin/remote/runner.py`）：

- `CannessAttrs::find` 改为成员函数模板 `find(const CharT*)`，复用私有 `findKey()`；设备字符串字面量、普通字符串字面量与本地 `char[]` 均可按名查找。**2026-11-24 真机复验后修正**：最初实现的 `find(const __gm__ char*)` 重载在 CANN 8.0.1 与 9.2.1 上都会与 `find(const char*)` 重定义——这两个版本把 `__gm__` 展开为 `cce_global` 属性，而属性不参与重载解析；模板方案同时满足 9.0.0 的地址空间语义与 8.0.1/9.2.1 的属性语义。
- 本地 host stub 不再需要 `CANNESS_LOCAL_VALIDATION` 条件编译（模板在地址空间被抹平时仍只有一个成员）。
- runner 的自检改为软门禁：自检超时/失败只写入 `compile.log` 和 `runRecord.params.contractSelfCheck`，不再提前返回，用户 kernel 的主编译照常执行；编译结果摘要会带 `contract self-check failed (template issue)` 提示。

**验证**：

- 新增 clang 双模型测试：用 `__attribute__((address_space(1)))` 模拟 9.0.0 的 `__gm__`，用 `__attribute__((cce_global))` 模拟 8.0.1/9.2.1 的属性语义，编译生成的 `canness_tiling.h`，覆盖 GM 数组、字符串字面量与本地数组三种 key。
- 新增 runner Python 单测：自检返回非零时用户构建仍执行且报告 `status=pass`，自检错误进入 compile log。
- 真机复验（2026-11-24）：CANN 8.0.1 / 910B3 与 CANN 9.2.1 docker / 910B2 上自检编译均通过，证据见 `issues/VERIFICATION-cann801-910b3-2026-11-23.md` 的“2026-11-24 补充”。

## CAN-103 没有受支持的修包 / 重签通道

**改动**（`plugin/src/package-files.ts`、`plugin/src/generator.ts`）：

- 新增 `repairPackage(workspace, generationId, { drop?, write? })` 与 `repair_package` 工具。
- `drop` 删除包内文件或目录；`write` 创建/替换文本文件（内容归一为 LF）。
- 路径校验：拒绝绝对路径、`..`、符号链接穿越和直接修改 `manifest.json`。
- 修补后重建 `manifest.files`，用与 `build_test_package` 相同的 `packageHash()` 重签，并同步 `.canness/state.json` 的 `packageHash` 与 `pendingStage`。

**验证**：单测覆盖删除 `.contract-selfcheck`、写新文件、重签一致性与路径逃逸拒绝。真机评测接受修补后的包待复验。

## CAN-104 packageHash 三真相源 / compile_only 被陈旧 state 拦住

**改动**（`plugin/src/eval.ts`、`plugin/src/eval-run.ts`）：

- `checkPackageHash()` 只以 `manifest.packageHash` 放行；`state.packageHash` 仅作为缓存，不再参与判定。错误文案同时给出 `manifest=…, state=…, actual=…`。
- `run_evaluation` 的 `compile_only` 分支跳过哈希门禁，只计算实际哈希供后续使用；`eval-run` 的 manifest 校验同样只在非 compile-only 时执行。

**验证**：新增单测覆盖三种情形——陈旧 state 不阻断正式评测、compile-only 忽略陈旧 manifest、manifest 不符时错误包含三方取值。真机 compile-only 待复验。
